# Learning Models as Functionals of Signed-Distance Fields for Manipulation Planning

- **Authors:** Danny Driess, Jung-Su Ha, Marc Toussaint, **Russ Tedrake**
- **Group role:** Last author (Tedrake). The work was done mainly at TU Berlin (Toussaint's lab), and Driess was a visiting researcher at MIT. Tedrake is formally the senior/last author, so it is assigned here. Toussaint is not a PI in the summary.

## Summary
Objects are represented as signed-distance fields (SDFs). The paper learns (i) a forward dynamics model that predicts the next SDF (or SDF flow) of an object given the motion of another object, i.e. a geometric world model for pushing, and (ii) kinematic "success" functionals (for example, whether a mug hangs on a hook). These learned functionals become constraints in a logic-geometric trajectory optimisation (TAMP) planner. SDF-based models predict more accurately and give better planning gradients than point-cloud or occupancy representations.

## 3. Datasets
All simulated in Bullet and generated by the authors; not released.
- **Mug hanging:** scenes with varied mug and hook shapes, 20 configurations per scene (mostly 1 success and 19 failures) (Sec. 7.1).
- **Pushing:** 14,975 scenes with boxes and L-shapes and spherical pushers of varying radii, random pushes biased toward the object centre. SDFs evaluated on a 140×140 2D grid (Sec. 7.2).
- An image-conditioned SDF variant is trained on rendered images (App. A.4).

## 4. Evaluation and downstream tasks
- **Forward prediction (Table 2, one-step SDF RMSE in mm):**
  - Flow model F_flow: 3.4±1.6 (contact) and 1.4±1.8 (no contact).
  - Direct model F: 5.8±1.7 and 5.2±1.6.
  - "No-motion" baseline: 10.8±3.4.
- **Representation comparison (App. A.6, Tables 4–5):** SDF-based models have lower prediction error than point-cloud (PointNet/PointNet++) and occupancy models.
- **Planning with the learned dynamics (pushing into a goal region, Fig. 3):** median object coverage inside the goal after open-loop execution in simulation is 99.7% (boxes) and 98.4% (L-shapes) with F_flow; 96.6% and 91.5% with F. 50 evaluation scenes each.
- **Comparison with analytic dynamics:** outperforms a mesh-based optimisation with an analytic pushing model (App. B, Fig. 6).
- **Generalisation demos (Fig. 4):** three-object interaction, two-arm collaborative pushing.
- **Mug hanging, kinematic model (Table 1):** 87.3% of scenes fully solved with SDF plus optimisation and sampling, vs 68.9% for sampling only, 52% for point cloud and 34% for occupancy.
- **Downstream tasks:** optimisation-based manipulation planning (TAMP) with learned dynamic and kinematic constraints.

## 5. Architecture and techniques
- **Representation:** object SDFs evaluated on a fixed grid X_h (2D 140×140 for pushing; 3D 40³ for mugs). The models are functionals of these SDFs.
- **Dynamics F / F_flow (App. I.1):**
  - A shared CNN encoder (3 conv layers plus a linear layer → 200-d) per SDF (object at t−1, pusher at t−1 and t), and a query-point encoder (→100-d).
  - Concatenated (700-d) into an MLP (2×300, ReLU) that outputs the SDF value (or flow increment) at the query point, so the output SDF can be queried at arbitrary x.
  - Quasi-static (history l=1).
- **Action conditioning:** no abstract action. The "action" is the motion of the pusher SDF, so different pusher geometries are handled.
- **Training loss:** squared SDF error integrated over the grid (Eq. 5). The same functional serves as the planning constraint H_F.
- **Planner:** logic-geometric programming / trajectory optimisation with discrete phase decisions (one or two pushes). It uses 4 fixed pusher initialisations per phase (20 problems per scene) and picks the plan with the lowest violation.

## 6. Conclusions and future work
- **Authors:** SDFs are a common representation across very different tasks. Models on SDFs beat point-cloud and occupancy models in accuracy and plannability. The main challenge is local minima in trajectory optimisation. Future work: extension to deformable objects.
- **Own observations:**
  - Evaluation is simulation-only (Bullet), with no real-robot experiment.
  - Execution is open-loop, and the dynamics model is used only one step ahead inside the optimiser.
  - SDFs are assumed to be available (ground truth or learned from images in an appendix).
  - Pushing is projected to 2D.
  - No code was released.
